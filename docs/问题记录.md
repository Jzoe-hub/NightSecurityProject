# 遇到的问题

## 问题 1: 加入 ESP8266 联网和 CommTask 后 STM32 不断重启

### 1. 现象

在已有传感器采集+判定+报警的基线上，新增 ESP8266 WiFi 模块驱动、CommTask（MQTT JSON 上报+下行命令处理）以及对应的队列后，烧录固件 OLED 画面不断在 "OLED OK" 初始化画面和传感器数据显示画面之间循环跳转，约每 2~5 秒一次。

### 2. 排查/解决步骤

| 步骤 | 操作 | 结果 | 说明 |
|------|------|------|------|
| 1 | 注释 EspRxTask + CommTask | 不重启 | 新任务相关 |
| 2 | 只恢复队列 (g_cloudRxQueue + g_cmdQueue) | 不重启 | 队列 OK |
| 3 | 恢复 EspRxTask (256 栈) + 心跳 | 重启 | EspRxTask 有问题 |
| 4 | 注释 Esp8266_Init() | 仍重启 | 不是 DMA 中断 |
| 5 | 注释看门狗 comm 心跳检查 | 不重启 | **CommTask 没运行！** |
| 6 | CommTask 栈 384→128 极限测试 | 不重启 | **堆内存不够** |
| 7 | SecurityTask 512→384, CommTask 128→256 | 不重启 | 堆平衡 OK |
| 8 | 恢复 CommTask 完整功能 + Esp8266_Init | ✅ | — |

### 3. 根因

`configTOTAL_HEAP_SIZE = 10240` (10KB) 不够。原有 5 个任务运行需 ~7.4KB，新增 ESP8266 联网功能后加了 CommTask (1616B) + 命令队列 (864B) + FreeRTOS 自带 TimerTask (1104B) = 总需求 ~11.2KB ＞ 10KB。`xTaskCreate(CommTask)` 的 `pvPortMalloc` 静默返回 NULL，CommTask 未创建。看门狗每 500ms 检查 `g_heartbeat_comm` 始终为 0 → 不喂狗 → IWDG 5 秒后复位。

### 4. 后续：指纹 FingerTask 启用时再次触发（同根因）

**现象**：启用指纹 FingerTask 后，STM32 再次出现和问题 1 完全一样的"OLED 初始化界面 ↔ 传感器数据界面循环跳转"。

**排查**：沿用问题 1 的结论直接定位——10KB 堆已在问题 1 中用到临界点，新增 FingerTask（TCB 88B + 栈 1024B ≈ 1.1KB）后必然溢出，FingerTask 创建失败，看门狗检查 `g_heartbeat_finger` 失败复位。

**解决**（累计省堆，最终余量 ~648B）：

| 改动 | 节省 |
|------|------|
| TimerTask 栈 256→100 words | 624B |
| SecurityTask 栈 384→320 words | 256B |
| UITask 栈 384→320 words | 256B |
| CloudRxPacket.json 192→128 字节 | 256B |
| g_cmdQueue 长度 4→2 | 264B |

**经验**：STM32F103C8T6 只有 20KB SRAM，FreeRTOS 堆固定 10KB，每加一个任务都要重新核算堆用量。任务栈、队列长度、缓冲区大小是三个可调旋钮。

## 问题 2: PIR 传感器拔掉后仍显示 P:1，触发入侵误报

### 1. 现象

PIR 人体红外传感器从板子上拔掉后，OLED 仍显示 `P:1`，SecurityTask 持续判定为入侵并触发报警。

### 2. 排查/解决步骤

1. 确认传感器确实已拔掉（排线断开）
2. 用万用表测 PA8 引脚电压：在 0~3.3V 之间随机跳变（悬空典型现象）
3. 查看 `Core/Src/gpio.c`：PA8 配置为 `GPIO_MODE_INPUT` + `GPIO_NOPULL`
4. 修改为 `GPIO_PULLDOWN`，让引脚悬空时默认低电平（无人）
5. 编译烧录，OLED 显示 `P:0` ✅

### 3. 根因

PA8 的 GPIO 配置为 `GPIO_NOPULL`。传感器拔掉后引脚悬空，CMOS 输入阻抗极高，电磁噪声使引脚电平随机漂移，恰好被读为高电平（有人）。

## 问题 3: MQ-2 烟雾传感器值始终为 0

### 1. 现象

OLED 监控页显示 `S:0`，MQ-2 烟雾传感器不输出任何数据。

### 2. 排查/解决步骤

1. 检查 MQ-2 模块供电 LED：正常亮，排除电源问题
2. 打火机靠近传感器：数值无变化
3. 重新插拔传感器排线：数值恢复 ✅

### 3. 根因

MQ-2 模块的 AO 模拟输出排线接触不良，ADC 端读到的是悬空电平 ≈ 0。

## 问题 4: LD2410C 雷达数据始终为 0

### 1. 现象

雷达模块在手机蓝牙 App 上工作正常（能检测到运动/静止目标），但 STM32 OLED 始终显示 `R:0`。

### 2. 排查/解决步骤

| 步骤 | 操作 | 结果 |
|------|------|------|
| 1 | 雷达 TX 单独接 USB-TTL，串口助手 25600 bps | 数据正常（F4 F3 F2 F1 帧头） |
| 2 | 查 `Radar_Init()` 调用 | **从未被调用！** 补加到 main.c |
| 3 | 查 USART1 中断/NVIC/DMA 配置 | 全部正确 |
| 4 | 测 PA10 引脚电压 | 3.27V（UART 空闲正常） |
| 5 | 借 USART2（与 ESP8266 共用，已验证正常）接雷达 | 数据仍为 0 |
| 6 | 显式开启 `__HAL_UART_ENABLE_IT(huart1, UART_IT_IDLE)` | 系统卡死 |

### 3. 根因

⚠️ **未解决**。雷达模块硬件正常（蓝牙 App 验证），代码逻辑正确（USART2 同模版运行正常），USART1 中断+DMA+引脚配置全部正确。高度怀疑 STM32F103C8T6 板载 PA10 引脚硬件异常。待换板验证。

## 问题 5: CubeMX 重新生成代码后系统崩溃

### 1. 现象

CubeMX 重新生成代码后：(1) 编译报 Flash 溢出 8 字节；(2) 烧录后卡在 OLED "OK" 初始界面不动。

### 2. 排查/解决步骤

1. 查链接错误：`-u _printf_float` 拉入大量浮点 printf 库代码，但项目已无 `%f` 格式化
2. 删除 `.cproject` 中 `-u _printf_float`，Flash 溢出消除
3. 发现 CubeMX 刷新了全部 HAL 库文件及部分手动配置，用 `git checkout` 恢复：
   - `FreeRTOSConfig.h`（Heap 大小等）
   - `freertos.c`（任务队列创建）
   - `gpio.c`（PIR 下拉已丢失）
   - `STM32F103C8TX_FLASH.ld`（_Min_Stack_Size）
   - `task_security.c`（阈值解析已丢失）
4. 手动补回 PIR 下拉配置 + SecurityTask 阈值解析代码
5. Clean → Build → Flash → 正常 ✅

### 3. 根因

CubeMX 重新生成会覆盖所有非 USER CODE 区域的代码（包括 `.cproject` 链接选项、`gpio.c` 引脚配置、`FreeRTOSConfig.h` 等），导致手动优化丢失。

## 问题 6: App 设置页阈值输入后切 Tab 丢失

### 1. 现象

在 App 设置页输入新阈值（如火焰 300），切到仪表盘再切回设置页，阈值恢复成默认值 2000。但 STM32 OLED 上的阈值已是修改后的值。

### 2. 排查/解决步骤

1. 查阈值存储方式：Compose `var thFire by remember { mutableStateOf("2000") }`
2. 确认 `remember` 生命周期：跟随 Composable，切 Tab 时 Composable 离开组合树 → 状态销毁
3. 将 5 个阈值字段从 Composable 本地 `remember` 移到 `SettingsViewModel` 的 `MutableStateFlow` 中
4. ViewModel 生命周期跟随 Activity，跨 Tab 不销毁
5. Build → Run → 阈值跨页面保持 ✅

### 3. 根因

Compose `remember` 的状态在 Composable 离开组合树时自动销毁。跨页面共享的状态必须放在 ViewModel 中。
