1. 程序是怎么跑起来的

STM32 的 Flash（闪存）是一排小格子，每个格子里存一条机器指令。在 CubeIDE 点「下载」，就是把编译好的程序按顺序塞进这排格子。

芯片一上电（复位），CPU 不会思考，只会做一件机械的事：从第 0 个格子（地址 0x08000000）开始，一条一条往下读、往下执行。

2. Bootloader 是什么：一个「管家」

核心死结：程序正在运行的时候，不能把自己覆盖掉。 就像开车时没法同时换自己的轮胎，得先停车，让一个「站在车外的人」来换。

Bootloader 就是这个「站在车外的人」，是写在 Flash 最前面的一段小程序：

  • 它永远不被升级、永远不动（换轮胎的人自己不能被换掉）
  • 它只干一件事：开机时检查「要不要升级」——要就换，不要（或换完）就把控制权交给 APP

类比电脑开机：先跑 BIOS（=Bootloader），再进 Windows（=APP）。重装系统是先重启进引导界面装，不是在 Windows 里删掉正在运行的 Windows。

3. OTA 是什么：负责「送货」

OTA = Over-The-Air，直译「通过无线/空中」。它只回答一个问题：新程序走哪条路送到设备手里？

  • 普通刷机：数据线（SWD 调试器）直接塞进 Flash
  • OTA 刷机：不插线，用网络送过来
名词负责的事类比
Bootloader收货、验货、安装程序帮你换轮胎的师傅
OTA把新程序送到设备面前送轮胎上门的快递

Bootloader 负责「装」，OTA 负责「送」，是搭档不是同一个东西。

4. 内存分区

程序的「家」在哪、有多大，由链接脚本（CubeIDE 工程根目录下的 .ld 文件，本项目是 STM32F103C8TX_FLASH.ld）决定，关键在 MEMORY 段。

MEMORY
{
  RAM    (xrw)    : ORIGIN = 0x20000000,   LENGTH = 20K
  FLASH    (rx)    : ORIGIN = 0x8000000,   LENGTH = 64K
}
词含义
ORIGIN起始地址 = 程序住进 Flash 的「第几格」
LENGTH总容量 = 从起点往后一共有多少格

本项目实际值（亲手读出）：FLASH 0x08000000 起、64K；RAM 0x20000000 起、20K。

做 Bootloader 的本质就是分区：把 APP 往后挪，最前面让给管家。

5. 中断向量表：一张「电话本」

芯片复位后，CPU 会去 Flash 最前面（第 0 格）翻一张表——中断向量表，它记录「每种突发事件（中断）该跳到哪里处理」。就像紧急电话本：火警→119、急救→120。

前两格是特例，复位时 CPU 唯一会用的就是它们：第 0 格放初始栈顶，第 1 格放复位函数。

6. VTOR 重映射

APP 搬到 0x08002000 后，它自己也有一张向量表。但 CPU 复位时是硬件写死的——永远先去 0x08000000 翻 Bootloader 的表。若跳转后不告诉 CPU「表换地方了」，APP 的中断会去翻错表，系统看起来能启动，但一有中断就崩/没反应。

解法：Bootloader 跳转前，设置 VTOR 寄存器（向量表偏移寄存器）：

SCB->VTOR = 0x08002000;   // 以后翻电话本，去 APP 这儿翻

7. 栈与栈顶

栈（Stack）是 RAM 里专门留出来的一块「临时存放区」，像一叠便签纸：调用函数往里压一张（压栈 push），返回往外拿一张（弹栈 pop），永远只能动最上面那张（后进先出）。

  • 栈顶 = 这叠便签最上面那张的位置
  • SP（栈指针） = 记录「现在栈顶在哪儿」的寄存器

复位第一步必须设栈顶，因为程序马上要调用函数、而调用函数就要压便签。栈顶 _estack = 0x20000000 + 20K = 0x20005000（RAM 最高处，栈从高地址往低地址长）。

概念关系总览：Flash 与 RAM

所有名词都能归到两块内存里：Flash（断电不丢，住的地方）和 RAM（断电就丢，干活的地方）。

口诀：程序住 Flash，干活用 RAM；向量表开在 Flash 最前面，第 0 格指向 RAM 的栈顶。

易混点：Bootloader 的「栈」和 APP 的「栈」不是两块独立内存——RAM 总共 20K，两个程序共用、轮流用。设栈顶 = 把 SP 拨回 RAM 顶端，让 APP 从头干净地用。

9. 跳转三步（设栈顶、读入口、跳转）· 已联调验证

跳转 = 手动模拟一次复位，对着 APP 的向量表重做开机的两拍。

#define APP_ADDR 0x08002000
typedef void (*pFunction)(void);

void jump_to_app(void)
{
    uint32_t appStack = *(volatile uint32_t*)APP_ADDR;                    // 第 0 格：栈顶
    pFunction appEntry = (pFunction)(*(volatile uint32_t*)(APP_ADDR+4)); // 第 1 格：入口
    SCB->VTOR = APP_ADDR;   // 切换向量表
    __set_MSP(appStack);    // 设栈顶
    appEntry();             // 跳转，永不返回
}

两个易错点：类型转换 `(pFunction)(*(volatile uint32_t*)(APP_ADDR+4))` 的 `*` 位置（先转指针 → 再解引用 → 再转函数指针类型）；`__set_MSP` 是函数（两个下划线），用法 `__set_MSP(appStack)` 不是赋值。

10. 写 Flash：先擦除，再编程

铁律：Flash 只能「1→0」，要「0→1」必须整页擦除（擦成 0xFF）。所以写 Flash 永远是两步：先擦除、再编程。

操作粒度
擦除1KB / 页（必须整页擦）
编程半字（2 字节 / 次）

HAL 四件套：HAL_FLASH_Unlock() 解锁 → HAL_FLASHEx_Erase() 擦页 → HAL_FLASH_Program() 编程 → HAL_FLASH_Lock() 上锁。

两个必须记住的坑：① 擦写期间要关中断（__disable_irq() 包住，因为 Flash 被改写时 CPU 不能从 Flash 取指令）；② 只用页擦除 FLASH_TYPEERASE_PAGES，绝不能整片擦（会把 Bootloader 自己也擦掉，变砖）。

11. CRC 校验：单帧 + 整包

两个层次：单帧 CRC 保证每一帧没传错；总 CRC 保证 400 多块合起来整体完整、没丢块、顺序没错。

START 帧带「总大小 + 总 CRC」，END 帧时把 Flash 里已写的固件整体重算一遍 CRC 比对：

uint16_t calc = crc16_modbus((uint8_t*)0x08002000, ota_total_size);
if (calc == ota_total_crc) { /* 校验通过 */ }

踩坑：函数要先声明后使用（C 从上往下编译），调用前加前置声明 static uint16_t crc16_modbus(...)。

12. 升级标志位：断电兜底的灵魂

Bootloader 只在「上电/复位」瞬间有控制权，所以 APP 想升级必须「写标志 → 重启 → Bootloader 查标志」。

标志位存 Flash 最后一页 0x0800FC00（不用 RTC Backup 寄存器，因为它依赖 VBAT 电池、真断电会丢 = 兜底失效）。

操作谁做怎么做
写标志APP（收到升级指令）擦标志页 + 写魔数 0x5AA5
查标志Bootloader（上电）读 *(uint16_t*)0x0800FC00 == 0x5AA5
清标志Bootloader（升级成功）擦标志页（擦成 0xFF）

断电兜底：升级到一半断电，标志还在（Flash 非易失），下次开机 Bootloader 还会查到标志、重进升级模式。这是标志位存在的核心价值。

13. APP 写标志 + 重启（闭环的另一半）

APP 不能自己覆盖自己，只能「写标志（告诉管家要升级）+ 重启（把控制权交回管家）」。标志页不在 APP 区，写它不会覆盖自己。

void OTA_EnterBootloader(void)
{
    /* 擦标志页 + 写魔数 0x5AA5 */
    ...
    NVIC_SystemReset();   // 重启 → Bootloader 接管（效果 = 按复位键）
}

两个踩坑：① 写标志 = 擦 + 写两步，漏了写魔数会白重启；② APP 的 USART2 用 DMA+IDLE 收帧，IDLE 中断触发一次后要重新调用 HAL_UARTEx_ReceiveToIdle_DMA 重启接收，否则收不到下一帧（原 AI 代码漏了重启）。

14. ESP8266 转发固件块（真无线）

ESP8266 是透明桥接：不碰固件内容，只搬运。手机发 MQTT → 封装成帧 → 发 STM32。

topic方向帧
/fw/start下行OTA_START（总大小+总CRC）
/fw/data下行OTA_DATA（块序号+数据）
/fw/end下行OTA_END
/fw/ack上行OTA_ACK（状态+块序号）

关键坑：① MQTT 包默认最大 128B，装不下固件块，要 #define MQTT_MAX_PACKET_SIZE 512（在 include 之前）；② 固件是二进制，不能用 JSON 字符串，用带长度的 publish。
