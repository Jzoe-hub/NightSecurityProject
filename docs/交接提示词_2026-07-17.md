# 项目交接提示词 — 2026-07-17

## 一、项目目标

在 STM32F103C8T6 硬件平台上从零构建一套**独居女性安防系统**：

- FreeRTOS 实时操作系统（10 个任务）
- MQTT 双向通信（ESP8266 + JSON）
- OTA 固件升级（STM32 Bootloader + ESP8266 HTTP 下载）
- Android APP（MVVM + Kotlin，Phase 5 之后）
- 全部代码由 CubeMX（STM32CubeIDE）生成工程框架，手写业务代码

## 六、下一步任务

### 立即可开始

1. **在 CubeIDE 中把 `Lib/src` 和 `Task/src` 加入编译路径**（右键 → Build Path → Add to Build）
2. **写第一个完整驱动** — 建议从 `pir.c/h` 开始（最简单，一行 `HAL_GPIO_ReadPin(PA8)`）
3. **写 `task_config.h`** — 声明全局句柄和队列
4. **在 `freertos.c` USER CODE RTOS_THREADS 区创建 SensorTask** — 用原生 FreeRTOS API `xTaskCreate()`
5. **写 `Task/src/task_sensor.c`** — 调用 Lib 驱动，读取传感器，发布到队列

### 后续

6. SensorTask → SecurityTask → AlarmTask 逐个实现
7. 任务间通信用 `xQueueSend` / `xQueueReceive`
8. Phase 2 完成标志：SensorTask + SecurityTask + AlarmTask 联调通过

## 七、Agent 必须遵守的规则

1. **重构计划是唯一事实来源** — 任何技术争论以 `docs/重构计划_从零开始.md` 为准
2. **先读计划再动手** — 不了解上下文时，先 Read 重构计划的相关章节
3. **CubeMX USER CODE 区** — freertos.c 只在 `USER CODE` 标记之间写代码，不碰标记外
4. **原生 FreeRTOS API** — 任务用 `xTaskCreate` / `vTaskDelay` / `vTaskDelayUntil`，不用 CMSIS_V2 的 `osThreadNew`
5. **互斥量风格** — 参考用户喜欢的模式：`GetXxx()` / `PutXxx()` 封装
6. **Lib 不依赖 FreeRTOS** — 驱动层只提供纯逻辑接口，不引用 FreeRTOS 头文件
7. **一个文件一个模块** — Lib 里 12 个独立驱动 + Task 里 10 个任务文件
8. **计划同步** — 任何技术决策变更必须同步更新重构计划
9. **Git 提交粒度** — 每完成一个小功能就 commit，不攒大块
10. **PC13 不用** — STM32F103C8T6 的 PC13 驱动能力不足，避免用于输出

## 九、已知风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 克隆 ST-Link 不稳定 | 调试困难 | Keil 擦除法 + BOOT0=1 强制复位可恢复 |
| SRAM 仅 20KB | 10 个任务可能栈溢出 | `CHECK_FOR_STACK_OVERFLOW` = Option 1，动态调栈 |
| PC13 备份域问题 | 不能用做常规 GPIO 输出 | 已放弃 PC13，用 PA5 和 RGB LED |
| CubeMX 重新生成 | 可能覆盖手写代码 | 所有手写代码在 USER CODE 区，不受影响 |
| ESP8266 文本解析 | 原参考工程用文本行解析，不可靠 | 计划要求改为二进制帧协议（带 CRC16） |
| Flash 寿命 10K 次 | 日志频繁写入可能磨损 | 需做磨损均衡（Phase 6） |
| 项目说明书、调试手册过时 | 内容基于旧参考工程（裸机架构），与新计划冲突 | Phase 2 任务跑通后重写 |
