# 项目交接提示词 — 2026-07-30

## 一、项目目标

在 STM32F103C8T6 硬件平台上从零构建一套**独居女性安防系统**：

- FreeRTOS 实时操作系统（10 个任务，当前 6 个已运行）
- MQTT 双向通信（ESP8266 + JSON，Phase 3）
- OTA 固件升级（Phase 4）
- Android APP（MVVM + Kotlin，Phase 5）
- 全部代码由 CubeMX 生成工程框架，原生 FreeRTOS API（xTaskCreate/vTaskDelay）写业务代码

**参考原项目**：`D:\keil.project2\NightSecurityProject\女性独家安防系统\`（裸机架构，算法和硬件接线可借鉴，代码不复用）。

6 个任务已创建并运行：
| 任务 | 优先级 | 栈 | 周期 | 功能 |
|------|--------|-----|------|------|
| SensorTask | 3 | 256 | 100ms | 读 8 类传感器，打包发队列 |

| WatchdogTask | 6 | 128 | 500ms | 心跳监控 + IWDG 喂狗 |

IPC 队列：`g_sensorQueue`（Sensor→Security）、`g_securityQueue`（Security→Alarm）

## 七、Agent 宪法（必须遵守）

1. **重构计划是唯一事实来源** — 技术争论以 `docs/重构计划_从零开始.md` 为准
2. **先读计划再动手** — 先 Read 相关章节
3. **CubeMX USER CODE 区** — `freertos.c` 和 `main.c` 只在 USER CODE 标记之间写
4. **原生 FreeRTOS API** — `xTaskCreate`/`vTaskDelay`，不用 CMSIS_V2 的 `osThreadNew`
5. **Lib 不依赖 FreeRTOS** — 驱动层只提供纯逻辑接口
6. **一个文件一个模块** — Lib 12 个独立驱动 + Task 10 个任务文件
7. **计划同步** — 技术决策变更必须更新重构计划
8. **Git 提交粒度** — 每完成一小功能就 commit
9. **PC13 不用** — 驱动能力不足
10. **注释风格** — 中文盒式（函数名称/功能描述/输入参数/返回值），宏/变量一行注释，函数盒式可以详细
11. **代码注释禁止引用文档路径** — 代码只描述自身，文档归文档
12. **宏/变量注释只写一行"是什么"** — 原理推导放 docs，不放代码
13. **来源标注** — 每个驱动文件标注原作者（辰哥/百问网/GitHub 等）
14. **用户写代码，Agent 指导** — 不要未经允许自己改函数体，只写框架骨架和注释

## 九、已知风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 克隆 ST-Link 不稳定 | 调试困难 | ST-Link GDB server + Under Reset + Hardware reset 模式；备选 BOOT0 擦除 |
| SRAM 仅 20KB | 10 个任务可能栈溢出 | `CHECK_FOR_STACK_OVERFLOW`=Option1，每个任务用 `uxTaskGetStackHighWaterMark()` 实测 |
| PC13 备份域 | 不能做输出 | 已放弃，用 PA5（蜂鸣器）和 RGB |
| CubeMX 重新生成 | 覆盖手写代码 | 手写代码只在 USER CODE 区 |
| Flash 寿命 10K 次 | 日志写入磨损 | Phase 6 做磨损均衡 |
| 蜂鸣器/RGB 极性 | 声光效果反了 | Buzzer 已修正（低触发），RGB 代码正确，PinState 待确认 |
| 指纹模块心跳 | FingerTask 死等会误触发看门狗 | 已注释，启用前把 `g_heartbeat_finger++` 放在 `finger_wait_touch` 之前 |
| 报警队列旧数据 | 撤防后残留报警命令 | AlarmTask 撤防时丢弃队列 + force mode=0 |
| 传感器阈值硬编码 | 与设置页不联动 | 已改为全局变量 `th_fire/th_smoke/th_co/th_temp/th_pir`，UI 和 SecurityTask 共享 |
