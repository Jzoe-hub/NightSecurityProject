# 女性安防系统 — 从零重构计划

> **原则**：完全从 STM32CubeMX 开始配置，重新生成工程，不复用现有裸机代码的架构，只复用硬件驱动逻辑。

---

## 一、项目目标

在现有硬件基础上，从零构建一个：

- **FreeRTOS** 实时操作系统驱动
- **MQTT** 双向通信（TLS 加密 + 遗嘱消息 + 心跳）
- **OTA 固件升级**（ESP8266 下载 → STM32 Bootloader 校验写入）
- **Android APP 重构**（MVVM + 通知 + 图表 + 多设备管理）

的**独居女性安防系统**。

## 三、CubeMX 配置清单

### 3.1 基础配置

```
MCU: STM32F103C8T6
Package: LQFP48
Clock: HSE 8MHz → PLL ×9 → SYSCLK 72MHz
       APB1 = 36MHz, APB2 = 72MHz
Debug: Serial Wire (SWD) — PA13, PA14（关闭 JTAG，释放 PB3/PB4 给 JQ8900）
Timebase: TIM4（SysTick 专供 FreeRTOS，TIM4 专供 HAL，避免抢占冲突）
```

### 3.2 FreeRTOS 配置

```
Middleware → FREERTOS → Interface: CMSIS_V2

Kernel Setting:
  - configUSE_PREEMPTION           = 1
  - configCPU_CLOCK_HZ            = SystemCoreClock (72MHz)
  - configTICK_RATE_HZ            = 1000
  - configMAX_PRIORITIES          = 56       (CMSIS_V2 固定: 7组×8子优先级)
  - configMINIMAL_STACK_SIZE      = 128 Words
  - configTOTAL_HEAP_SIZE         = 10240    (10KB, 保守)
  - configMAX_TASK_NAME_LEN       = 16
  - configUSE_16_BIT_TICKS        = Disabled (0 → 32位, 最长49.7天不溢出)
  - configIDLE_SHOULD_YIELD       = Enabled
  - configCHECK_FOR_STACK_OVERFLOW = Option 1 (开发阶段必开, 任务栈溢出时检测)
  - configUSE_MUTEXES             = Enabled
  - configUSE_RECURSIVE_MUTEXES   = Enabled
  - configUSE_COUNTING_SEMAPHORES = Enabled
  - configUSE_QUEUE_SETS          = Enabled (SecurityTask 同时等传感器队列+命令队列)
  - configUSE_TASK_NOTIFICATIONS  = Enabled (WatchdogTask 心跳检测, 比信号量快)
  - configUSE_TIMERS              = Enabled
  - configTIMER_TASK_STACK_DEPTH  = 256
  - configTIMER_QUEUE_LENGTH      = 10
  - configTIMER_TASK_PRIORITY     = 2

Memory Management:
  - Memory Allocation: Dynamic / Static
  - TOTAL_HEAP_SIZE: 10240 Bytes
  - Memory Management scheme: heap_4 (支持相邻空闲块合并, 避免碎片化)

CMSIS_V2 标志 (CubeMX 自动配置):
  - USE_OS2_THREAD_SUSPEND_RESUME = 1  (对应 vTaskSuspend)
  - USE_OS2_THREAD_ENUMERATE      = 1
  - USE_OS2_EVENTFLAGS_FROM_ISR   = 1
  - USE_OS2_THREAD_FLAGS          = 1  (任务通知)
  - USE_OS2_TIMER                 = 1
  - USE_OS2_MUTEX                 = 1

注意: USE_IDLE_HOOK = Disabled, 看门狗喂狗不放在空闲钩子,
     而是由 WatchdogTask (优先级6) 每500ms检查各任务心跳后统一喂狗
```

### 3.3 外设配置

#### ADC1（烟雾 + CO + 火焰）

```
ADC1 → Channel 0 (PA0): MQ-2 烟雾传感器
ADC1 → Channel 1 (PA1): MQ-7 CO 传感器
ADC1 → Channel 4 (PA4): 火焰传感器 AO (四线模块)
Mode: Independent mode, Continuous conversion = DISABLE (由定时器触发)
Sampling Time: 239.5 Cycles
DMA: DMA1 Channel1, Circular, Half-Word (扫描 3 个通道)
```

#### USART1（LD2410C 雷达）

```
Mode: Asynchronous
Baud Rate: 25600
Word Length: 8 Bits, Parity: None, Stop Bits: 1
RX Pin: PA10, TX Pin: PA9
NVIC: USART1 Global Interrupt = ENABLE
DMA: DMA1 Channel5 (RX), Circular, Byte

注意: LD2410C 默认波特率为 25600，帧头为 FD FC FB FA
```

#### USART2（ESP8266 WiFi 模块）

```
Mode: Asynchronous
Baud Rate: 115200
Word Length: 8 Bits, Parity: None, Stop Bits: 1
RX Pin: PA3, TX Pin: PA2
NVIC: USART2 Global Interrupt = ENABLE
DMA: DMA1 Channel6 (RX), Circular, Byte
```

#### USART3（ZW101 指纹模块）

```
Mode: Asynchronous
Baud Rate: 57600
Word Length: 8 Bits, Parity: None, Stop Bits: 1
RX Pin: PB11, TX Pin: PB10
NVIC: USART3 Global Interrupt = ENABLE

注意: ZW101 协议与 AS608 兼容(同为 EF01 帧头 + FFFFFFFF 地址码 + 校验和)，
      PIN1 V_SENSOR 必须常接 3.3V 供电(否则无法采指纹图像)
```

#### I2C1（OLED 显示屏）

```
Mode: I2C
Speed: Fast Mode (400KHz)
SCL: PB8, SDA: PB9
```

#### TIM2（微秒时基 / DHT11 时序）

```
Clock Source: Internal Clock
Prescaler: 72-1 → 1MHz (1µs tick)
Counter Period: 65535 → 最大计时 65ms
NVIC: TIM2 Global Interrupt = ENABLE

作用：FreeRTOS vTaskDelay 最小单位 1ms, DHT11 需要 µs 级延时
      (起始信号 18ms, 应答 80µs), 用 TIM2 的 CNT 计数器实现 delay_us()
```

#### TIM3（传感器采样定时器）

```
Clock Source: Internal Clock
Prescaler: 7200-1 → 10KHz
Counter Period: 1000-1 → 100ms 周期
Trigger Output: Update Event (TRGO) → 触发 ADC 转换
NVIC: TIM3 Global Interrupt = ENABLE

作用：硬件定时器 100ms 精确触发 ADC 采样, 比 vTaskDelay 累积误差更小
      在 HAL_TIM_PeriodElapsedCallback 中调用 HAL_ADC_Start_DMA()
```

#### GPIO 输入

```
PA6  - ZW101 TOUCH     (浮空输入, EXTI 上升沿中断, 模块主动输出, 1=活体真/0=活体假)
PB5  - LD2410C OT1     (浮空输入, EXTI 双沿中断, 有人=高电平 无人=低电平)
PA8  - HC-SR501 PIR    (浮空输入)
PA11 - 火焰传感器 DO    (上拉输入, 数字过阈值触发)
PB12 - JQ8900 BUSY     (浮空输入)
PB13 - K1 按键         (上拉输入, EXTI 下降沿中断)
PB14 - K2 按键         (上拉输入, EXTI 下降沿中断)
PB15 - K3 按键         (上拉输入, EXTI 下降沿中断)
```

#### GPIO 输出

```
PA5  - 蜂鸣器       (推挽输出, 低电平触发)
PA7  - RGB-B (蓝灯) (推挽输出, 低电平有效)
PB0  - RGB-R (红灯) (推挽输出, 低电平有效)
PB1  - RGB-G (绿灯) (推挽输出, 低电平有效)
PB6  - JQ8900 IO1   (推挽输出, 低电平脉冲触发) — 火灾报警
PB7  - JQ8900 IO2   (推挽输出, 低电平脉冲触发) — 入侵报警
PB3  - JQ8900 IO3   (推挽输出, 低电平脉冲触发) — 指纹认证成功
PB4  - JQ8900 IO4   (推挽输出, 低电平脉冲触发) — 撤防成功
PA12 - DHT11 DATA   (开漏输出, 需要切换输入/输出)
PB12 - JQ8900 BUSY  (输入, 播放中=高电平)
```

#### IWDG（独立看门狗）

```
Prescaler: 64 → IWDG_CLK = 40KHz LSI ÷ 64 = 625Hz
Reload: 625 → 超时 ≈ 1.6s
喂狗方式: WatchdogTask (优先级6) 每500ms检查各任务心跳后 HAL_IWDG_Refresh()

注意: 不放在空闲钩子。空闲任务可能在正常阻塞时一直跑(假健康),
      WatchdogTask 通过任务心跳检测能发现"某个关键任务死了但空闲任务还在跑"的真死机。
```

#### RTC（实时时钟）

```
配置步骤:
  1. System Core → RCC → Low Speed Clock (LSE) → Crystal/Ceramic Resonator
  2. System Core → RTC → Activate Clock Source (勾上即可, 自动走 LSE)
  3. Calendar Time/Date 设初始值 (后续通过 MQTT 从 APP 同步校准)

Clock Source: LSE (外部 32.768KHz 晶振), 精度远高于内部 LSI

用途: Phase 2 报警日志时间戳 + 定时布防/撤防 (如"每晚22:00自动布防")
```

## 四、FreeRTOS 任务设计

### 4.1 任务总表

| 任务名           | 优先级      | 栈大小 | 周期/触发 | 核心职责                                                   |
| ---------------- | ----------- | ------ | --------- | ---------------------------------------------------------- |
| `SensorTask`   | 3 (Normal)  | 256    | 100ms     | 读取所有传感器，滤波，发布传感器事件                       |
| `SecurityTask` | 4 (High)    | 512    | 100ms     | 火灾/入侵融合判定，状态机运转，**定时布防/撤防调度** |
| `AlarmTask`    | 5 (Highest) | 256    | 50ms      | 声光报警时序（蜂鸣器PWM、RGB闪烁、语音触发）               |
| `CommTask`     | 3 (Normal)  | 512    | 事件驱动  | MQTT 协议包装/解析，JSON 构建/解析                         |
| `EspRxTask`    | 4 (High)    | 256    | 事件驱动  | ESP8266 串口数据接收、帧同步                               |
| `UITask`       | 2 (Low)     | 384    | 200ms     | OLED 刷新，按键响应，菜单状态机                            |
| `FingerTask`   | 2 (Low)     | 384    | 事件驱动  | 指纹录入/验证/删除流程                                     |
| `OTATask`      | 1 (Lowest)  | 512    | 按需      | OTA 固件接收、Flash 写入、校验                             |
| `WatchdogTask` | 6 (Max-1)   | 128    | 500ms     | 各任务心跳检测 + IWDG 喂狗                                 |
| `LogTask`      | 1 (Lowest)  | 256    | 按需      | 报警日志写入内部 Flash                                     |

### 4.2 任务间通信（IPC）

```

SensorTask ──Queue──→ SecurityTask     (传感器数据包)
SecurityTask──Queue──→ AlarmTask       (报警命令: 类型/等级)
SecurityTask──Queue──→ CommTask        (状态上报请求)
CommTask ──Queue──→ SecurityTask       (APP 下发命令: 布防/撤防/阈值)
CommTask ──Queue──→ OTATask            (OTA 数据块)
EspRxTask ──Queue──→ CommTask          (ESP8266 原始帧)
FingerTask──EventGroup→ SecurityTask   (指纹验证结果事件)
SecurityTask──Queue──→ LogTask         (报警日志写入)
Key ISR ──Queue──→ UITask              (按键事件)
```

**task_sensor.c 示例** — 任务函数:

```c
#include "task_config.h"
#include "lib_sensor.h"
#include "main.h"

void SensorTask(void *param) {
    TickType_t xLastWakeTime = xTaskGetTickCount();
    for (;;) {
        /* 读全部传感器 */
        SensorData_t data;
        Sensor_ReadAll(&data);

        /* 发给 SecurityTask */
        xQueueSend(g_sensorQueue, &data, 0);

        vTaskDelayUntil(&xLastWakeTime, pdMS_TO_TICKS(100));
    }
}
```

## 五、核心模块设计

### 5.0 LD2410C 雷达协议解析

```

═══════════════════════════════════════════
LD2410C 数据帧格式 (UART 上报)
═══════════════════════════════════════════

帧结构 (固定长度 30 字节):
┌──────┬──────┬──────┬──────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┐
│  FD  │  FC  │  FB  │  FA  │ LEN │ STA │ MOT │ EN_M│ EN_S │ DIS │     │M_DIST│     │S_DIST│     │M_DIST│     │S_DIST│     │M_DIST│     │S_DIST│     │ CHK  │  END  │
│ 0xFD │ 0xFC │ 0xFB │ 0xFA │0x1A │     │     │     │     │_M_L │     │(LSB) │     │(LSB) │     │  #2  │     │  #2  │     │  #3  │     │  #3  │     │      │ 0x55  │
└──────┴──────┴──────┴──────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘

关键字段:
  STA (State):        bit0=有人/无人, bit1=运动触发, bit2=静止触发
  MOT (Motion):       0=无运动目标, 1=有运动目标
  EN_M (Motion Energy): 运动能量值 0-100
  EN_S (Static Energy): 静止能量值 0-100
  DIS_M_L/H:           运动目标距离 (cm)
  S_DIST_L/H:          静止目标距离 (cm)
  CHK:                 校验和 (前 28 字节累加取低 8 位)
  END:                 0x55 帧尾

OT1 引脚:

- 输出高低电平指示是否有人 (可通过上位机配置)
- 高电平 = 有人 (运动或静止)
- 低电平 = 无人
- 接 STM32 PA4, EXTI 双沿中断 → 快速响应人员进入/离开
- UART 数据作二级确认 (防止 OT1 毛刺误触发)

解析流程:

1. DMA 循环接收 USART1 数据到环形缓冲区
2. 在 SensorTask 中扫描帧头 FD FC FB FA
3. 验证 LEN == 0x1A 且帧尾 == 0x55
4. 累加校验和验证
5. 提取: has_motion, has_static, motion_energy, static_energy, motion_dist, static_dist
6. 发布到 SecurityTask 的消息队列
```

### 5.2 火灾判定算法

```

输入: val_temp, val_smoke, val_gas, val_flame_ao, val_flame_do

滤波:

- smoke:      Kalman + EWMA (λ=0.15)
- gas:        Kalman + EWMA (λ=0.15)
- flame_ao:   均值滤波 (窗口=3)
- temp:        均值滤波 (窗口=5)

超阈值检测:

- temp_over   = (val_temp     >= th_temp)
- smoke_over  = (val_smoke    >= th_smoke)
- gas_over    = (val_gas      >= th_gas)
- flame_do_on = (val_flame_do > 0)           // 数字量快速触发
- flame_ao_on = (val_flame_ao >= th_flame)   // 模拟量确认

评分 (火焰权重从 5 提升到 20):
  fire_score = temp_over×70 + smoke_over×55 + gas_over×40
             + (flame_ao_on ? 20 : 0) + (flame_do_on ? 10 : 0)

状态转移:
  IDLE/ARMED:
    - flame_do 触发但 flame_ao 未达阈值 → WARNING (单独火焰数字量可能是误报)
    - 单传感器触发 → WARNING (启动 5s 确认窗口)
    - 双传感器触发 → ALARM
    - fire_score >= 60 → ALARM
  WARNING:
    - 5s 内第二个传感器触发 → ALARM
    - 5s 内原传感器消失 → IDLE/ARMED
    - 5s 超时 → 根据剩余触发源判定

四线火焰传感器优势:

- DO 用作快速触发 (与其他传感器组合判定)
- AO 提供火焰强度连续值，可设定精确阈值 + 滤波
- flame_ao + flame_do 同时触发 → 高置信度明火
```

### 5.3 入侵判定算法

```

输入: pir_raw, radar_motion_energy, radar_static_energy, radar_motion_dist, radar_static_dist

LD2410C 上报数据:

- 帧头: FD FC FB FA
- 运动目标状态: 0=无人 / 1=有人移动
- 静止目标状态: 0=无人 / 1=有人静止
- 运动能量值: 0-100 (数值越大越活跃)
- 静止能量值: 0-100 (数值越大越确定有人)
- 运动距离: cm
- 静止距离: cm

滤波:

- intrusion_value: EWMA (α=0.25)

评分:
  pir_contribution        = (pir_raw > 0) ? 70 : 0
  radar_motion_contrib     = (radar_has_motion)  ? 25 : 0
  radar_static_contrib     = (radar_has_static)  ? 50 : 0  // 静止人体 = 高置信度
  radar_nearby_contrib     = (radar_any_dist < 200cm) ? 15 : 0  // 距离近加分

  intrusion_input = pir_contribution + radar_motion_contrib
                  + radar_static_contrib + radar_nearby_contrib
  intrusion_score = Ewma_Update(&intrusion_ewma, intrusion_input)

状态转移:

- intrusion_score >= 60 → INTRUSION_ALARM
- 静止人体检测到 + 距离 < 100cm → 高置信度，直接触发 ALARM
- 仅运动检测(无静止) → 提升到 WARNING，等待二次确认

LD2410C 优势:

- 可检测静止人体(呼吸微动)，入侵者蹲伏不动也能发现
- 输出能量值可做二级滤波，比简单 0/1 更可靠
```

### 5.5 定时布防/撤防

```

═══════════════════════════════════════════
实现方案
═══════════════════════════════════════════

依赖: RTC (已在 CubeMX 配置，LSE 32.768KHz)

SecurityTask 每个周期 (100ms) 追加一步:

1. 从 RTC 读取当前 HH:MM
2. 遍历配置中的定时规则列表 (最多 N 条)
3. 如果 "当前时间 == 规则时间" 且 "今天还未触发过":
   → 布防: sw_security = 1
   → 撤防: sw_security = 0
   → 标记已触发
4. 如果 "当前时间 != 规则时间":
   → 清除触发标记 (为下一天准备)

数据结构 (存储在 Flash 配置区):
```

```c
#define MAX_SCHEDULE_RULES 8

typedef enum {
    SCHED_ACTION_ARM   = 1,  // 布防
    SCHED_ACTION_DISARM = 0,  // 撤防
} SchedAction;

typedef struct {
    uint8_t  hour;        // 0-23
    uint8_t  minute;      // 0-59
    uint8_t  action;      // 1=布防, 0=撤防
    uint8_t  repeat_mask; // bit0=周一 ... bit6=周日, 0xFF=每天
    uint8_t  enabled;     // 0=禁用, 1=启用
} ScheduleRule;

typedef struct {
    ScheduleRule rules[MAX_SCHEDULE_RULES];
    uint8_t today_triggered_bitmap; // 每 bit 对应一条规则当天是否已触发
    uint8_t last_check_day;         // 换天时清零
} ScheduleConfig;
```

典型使用场景:
  规则1: 22:00 布防, 每天 → 晚上10点自动设防
  规则2: 07:00 撤防, 每天 → 早上7点自动撤防
  规则3: 09:00 布防, 周一~周五 → 工作日出门后自动设防

防重复触发:

- 用 today_triggered_bitmap 记录每条规则今天是否已执行
- 每次 RTC 日期变更时清零
- 避免在 22:00 这一分钟内反复触发多次

### 6.2 STM32 Bootloader 设计

```

Bootloader 入口 (0x08000000):

1. 检查 OTA 标志位 (备份寄存器或 Flash 最后一页)
2. 如果无 OTA 请求:
   - 校验 APP 区栈顶地址合法
   - 设置 VTOR = 0x08004000
   - 跳转到 APP 复位向量
3. 如果有 OTA 请求:
   - 初始化 USART2 (与 ESP8266 通信)
   - 等待 OTA 数据包
   - 每收到一个 block:
     a. 验证 block index 连续性
     b. 写入 Flash (0x08004000 + block_index * 1024)
     c. 回复 ACK/NAK
   - 收到 OTA_FINISH:
     a. 全固件 CRC32 校验
     b. 校验通过 → 清除 OTA 标志，软复位
     c. 校验失败 → 回复错误，等待重发

```

## 十、注意事项

1. **CubeMX FreeRTOS 版本**：CubeMX 自带的 FreeRTOS 版本可能较旧（一般 CMSIS_RTOS_V2 wrapper），推荐使用 CubeMX 包管理器下载最新版。
2. **ESP8266 帧协议**：一定要从现有的"文本行解析"改为**二进制帧协议**（带 CRC 校验），否则 OTA 传输不可靠。
3. **MCU Flash 寿命**：STM32F103C8T6 Flash 擦写次数约 10,000 次。报警日志和配置存储需做磨损均衡（每次写不同位置，循环使用）。
4. **OTA 安全性**：

   - 固件必须做完整性校验（CRC32 + MD5）
   - 必须做版本号检查（不能降级到旧版本有已知漏洞的固件）
   - 可选：固件数字签名（RSA/ECDSA），防止恶意固件
5. **MQTT Broker**：目前用的是公网 IP `117.72.167.226:1883`，建议：

   - 开发阶段：自建 Mosquitto (Docker) 或使用 EMQX Cloud 免费版
   - 生产阶段：阿里云 IoT / 华为云 IoT，自带设备管理和 OTA 服务
6. **SRAM 预算**：STM32F103C8T6 只有 20KB SRAM，需要精打细算：

   - FreeRTOS heap: 10KB
   - 任务栈: 约 3KB
   - 驱动 buffer: 约 2KB
   - 用户数据: 约 3KB
   - 余量: 约 2KB

   建议所有 Buffer 用静态分配，OTA 传输时用流式写入避免大量缓存。
